# Port map

| Port | Proto | Direction / binding     | Purpose                                                                     | Configured in                                                                                                                                                                                                                        |
| ---- | ----- | ----------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 8300 | TCP   | Inbound, host loopback  | App HTTP in development and production                                      | `vite.config.ts` (`server`/`preview`), `deno.jsonc` (`start`, `preview`), `compose.yml` (`127.0.0.1:8300:8300`), `compose.dev.yml` (`8300:8300`, dev only), Windows `-AppPort` in `Setup-Production.ps1` and `Register-Services.ps1` |
| 8301 | TCP   | Inbound, host loopback  | Alternate app HTTP instance                                                 | `deno.jsonc` task `start:alt` only                                                                                                                                                                                                   |
| 5432 | TCP   | Inbound, host loopback  | PostgreSQL                                                                  | `compose.yml` (`127.0.0.1:${POSTGRES_PORT:-5432}:5432`), native PostgreSQL 16 (`PgPort` parameter), `DATABASE_URL` in `.env`                                                                                                         |
| 80   | TCP   | Inbound, Windows native | Caddy HTTP: ACME challenge and IP-mode dashboard                            | `deploy/windows/Caddyfile`, Caddyfile generated by `Setup-Production.ps1`, firewall rule created by setup                                                                                                                            |
| 443  | TCP   | Inbound, Windows native | Caddy HTTPS when `-Hostname` is set                                         | `deploy/windows/Caddyfile`, Caddyfile generated by `Setup-Production.ps1`, firewall rule created by setup                                                                                                                            |
| 443  | TCP   | Outbound                | Upstream CMMS (Fracttal) API and alert provider; Caddy certificate services | `FRACTTAL_*` and `ALERT_PROVIDER_*` settings in `.env`; Caddy automatic HTTPS                                                                                                                                                        |
| 9333 | TCP   | Inbound, host loopback  | Chrome DevTools Protocol for `scripts/browser-smoke.ts`                     | `scripts/browser-smoke.ts` (`--remote-debugging-port=9333`)                                                                                                                                                                          |
| 9336 | TCP   | Inbound, host loopback  | Chrome DevTools Protocol for `scripts/browser-capture.ts`                   | `scripts/browser-capture.ts` (`--remote-debugging-port=9336`)                                                                                                                                                                        |

Ports are set in the repository, not only by the process runner: Vite dev and
preview, Deno tasks, Compose mappings and Windows setup parameters all carry
them. Production Compose binds 8300 and 5432 to `127.0.0.1`. The development
override (`compose.dev.yml`) maps `8300:8300` on all host interfaces; that
exposure is dev-only. `deploy/check-compose-prod.sh` fails when `compose.yml`
stops loopback-binding 8300 or 5432.

Windows native default-denies inbound traffic. Setup opens 80, plus 443 when a
hostname is configured, only when `-AllowedLanRanges` scopes them to the client
network. Port 8300 stays on loopback unless `-SkipCaddy -AllowLanAppPort` is
combined with ranges, which serves plain HTTP and is acceptable only behind a
VPN. Compose does not change host firewall rules; its public surface is limited
to the loopback mappings above.

See [DEPLOY-WINDOWS.md](./DEPLOY-WINDOWS.md) for install, firewall and
operations detail.
